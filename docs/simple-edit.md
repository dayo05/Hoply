# Simple Edit

## 서식 고정

문서는 읽기 전용으로 열고, Edit를 누르면 별도의 SVG 레이어에만 입력한다.
원본 rhwp 문서 모델과 원본 SVG는 편집하지 않는다. 표 셀을 탭하는 동작도 입력 영역을
선택할 뿐, 셀·문단·줄 정보를 바꾸지 않는다. 입력은 페이지 좌표로 보관하고,
고정 영역을 넘는 텍스트는 적용을 막는다. 실행 취소와 지우개도 새 입력에만 작용한다.

작성본 HWP에서는 **원본의 모든 쪽을 고정된 페이지 배경으로 변환한다.**
원본 표·글자의 구조, 원본 글자 검색·선택, 기존 필드·하이퍼링크·접근성 구조는
작성본에 유지되지 않는다. 새 입력은 한글의 편집 가능한 글상자이고,
서명은 별도의 투명 PNG 그림이다. 배경 이미지와 서명도 한글의 그림 개체이므로
다른 앱에서 개체 자체를 편집하면 바뀔 수 있다. 문서 보호나 위변조 방지 기능은 아니다.
원본 파일과 기기 내 편집 초안은 별도로 유지한다.

## HWP 생성과 검증

1. 모든 원본 쪽을 표시하고 글꼴 로딩을 기다린다. 페이지별 SVG ID 보정과 기존 셀의
   마지막 글자 잘림 보정이 반영된 원본 SVG만 사용한다. 편집 레이어는 배경에 합치지 않는다.
2. 원본 SVG를 흰색 바탕의 PNG로 만든다. 일반 용지는 CSS 크기의 3배(약 288 dpi)이며,
   쪽당 1,200만 픽셀과 한 변 8,192픽셀 이내로 제한한다. 확대 시 벡터 원본과 달리
   래스터 이미지의 해상도 한계와 안티앨리어싱 차이가 있다.
3. 새 HWP 5 템플릿에 빈 호스트 문단을 먼저 모두 만든다. rhwp의 문단 삽입은 기존
   개체를 다음 문단으로 옮기므로 배경을 배치한 뒤 문단을 추가하지 않는다.
4. 배경은 용지 기준 (0, 0), 원래 쪽 크기, 비인라인, `BehindText`로 놓는다.
   새 글상자와 서명은 `InFrontOfText`로 놓는다. 그림 API는 zOrder 변경을 지원하지
   않으므로 배경을 앞쪽 면에 놓고 zOrder만 낮추는 방법을 쓰지 않는다.
5. 새 글자는 줄마다 투명하고 크기가 고정된 글상자에 넣는다. 기존 표가 커지거나
   기존 문단이 밀려날 수 있는 구조가 작성본에 없다.
6. 생성한 문단을 쪽마다 별도 구역으로 나누고 해당 쪽의 용지 크기와 여백 0을 명시한다.
   가로·세로 또는 여러 용지 크기가 섞여 있어도 각 쪽의 크기를 유지한다.
   새 문서의 리소스 ID는 한 생성기에서 관리해 구역끼리 충돌하지 않게 한다.
7. rhwp 빈 문서 템플릿의 0 버전을 HWP 5.1.1.0으로 정규화한다. CFB의 미사용 FAT /
   MiniFAT 항목은 `FREESECT`로 정규화해 엄격한 CFB 파서도 읽을 수 있게 한다.
8. 저장본을 같은 rhwp로 다시 연다. 쪽 수·용지 크기·배경 위치·크기·그리기 면과
   배경 PNG 바이트가 일치해야 바이트를 네이티브로 넘긴다. 원본 파일은 덮어쓰지 않는다.

이 경로는 원본 레코드를 재직렬화하지 않으므로 HWP/HWPX 등 앱에서 표시 가능한
문서를 같은 방식으로 HWP 5 작성본에 넣는다. 새 글꼴의 대체나 다른 앱에서 사용자가
개체를 수정한 뒤의 배치까지 고정하는 검사는 아니다.

## 자동 보관과 출력

입력은 Application Support의 SimpleEdit에 JSON으로 원자적으로 저장한다.
문서 원본 SHA-256과 로컬 파일명을 함께 사용해 가져온 사본끼리 입력이 섞이지 않게 한다.
파일명이나 원본 내용이 바뀌면 새 문서로 취급한다. 렌더러 버전과 쪽 크기도 보관하며,
다른 렌더링 기준의 초안을 자동으로 덧씌우지 않는다. 아직 적용하지 않은 입력창 내용은
저장되지 않는다. 기기 내 보관이며 iCloud 동기화 기능은 아니다.

작성본을 Hoply에서 새 파일로 열면 이전 입력도 그 파일의 원본 내용으로 취급한다.
기존 입력을 계속 수정하려면 기기에 보관된 원본 문서의 초안을 열거나, 다른 한글 앱에서
작성본의 글상자를 편집한다. 작성본 HWP에 Hoply 초안 JSON을 포함하지 않는다.

원본 공유는 원본 URL을, HWP 공유는 새 임시 파일을 사용한다. PDF는 각 쪽을 별도로
캡처해 원래 용지 크기와 쪽 수로 합친다. 인쇄도 같은 PDF 경로를 사용한다.
출력 중에는 문서 닫기와 편집 입력을 막아 중간 상태가 섞이지 않게 한다.

## 검증

```bash
npm run build:viewer
npm run ios:typecheck
npm run test:viewer
PLAYWRIGHT_BROWSER=webkit node --experimental-strip-types --test web-viewer/tests/simple-edit.test.mjs
```

`PLAYWRIGHT_CHROMIUM_EXECUTABLE_PATH`와 `PLAYWRIGHT_BROWSERS_PATH`로 설치된 브라우저를
지정할 수 있다. `HOPLY_HWP_TEST_FILE`을 지정하면 개인 문서를 저장소에 복사하지 않고
HWP 왕복 검사를 실행한다. 출력 문서와 개인 문서는 저장소에 포함하지 않는다.

자동 검사는 원본 SVG 불변, 영역 넘침 차단, 필기·지우개·실행 취소, 확대 위치 정합,
HWP 재읽기, 쪽별 배경과 입력 분리, 혼합 용지, 배경 픽셀, 글상자 재편집을 확인한다.

2026-11-05 확인: Chromium 전체 16개, WebKit Simple Edit 6개 통과. 로컬 HWP 양식
5개와 저장소 HWPX 샘플의 HWP 저장 검사를 통과했으며, 이전 경로에서 배치가 바뀌던
11쪽 양식도 Chromium과 WebKit에서 통과했다. 엄격한 rhwp CLI 파싱과 8쪽 작성본의
PDF 렌더링·육안 검사를 완료했다. Swift 검사와 실기기용 arm64 IPA 빌드도 통과했다.
실제 Apple Pencil의 지연·팜 리젝션과 iOS 공유·인쇄는 기기에서 별도로 확인해야 한다.
